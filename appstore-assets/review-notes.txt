AirWSJT-X is a ham (amateur) radio application for aircraft-scatter communication on microwave frequencies (1296 MHz and above). No login or account is required.

WHY THE NETWORK SERVER ENTITLEMENT IS REQUIRED

The macOS app intentionally uses com.apple.security.network.server for its core WSJT-X integration. AirWSJT-X acts as a UDP protocol listener: its bundled helper binds UDP port 2237 and receives heartbeat, status, decode, and QSO Logged datagrams sent by the separate WSJT-X application. Those inbound datagrams drive the app's WSJT-X connection indicator, decoded-message list, frequency/mode state, and QSO workflow.

The default setup uses the WSJT-X multicast group 224.0.0.1 on UDP port 2237 so compatible logging applications may share the feed. Loopback or a local-network address can also be configured. AirWSJT-X accepts only WSJT-X/JTDX protocol messages and ignores unrelated application identifiers. It is not a general-purpose web, FTP, or file server. Removing com.apple.security.network.server prevents the sandboxed app from binding the UDP listener and breaks this advertised functionality.

HOW TO VERIFY THE INBOUND LISTENER

1. Install and launch WSJT-X 2.6 or later on the same Mac.
2. In WSJT-X, open Settings > Reporting.
3. Set UDP Server to 224.0.0.1 and UDP Server port to 2237, then apply the settings.
4. Launch AirWSJT-X. The WSJT-X status at the top changes from Disconnected to Connected after heartbeat/status datagrams arrive.
5. Start monitoring in WSJT-X. Decoded messages received over UDP appear in AirWSJT-X's Decodes panel.

Without WSJT-X running, Disconnected is expected and the entitlement cannot be exercised. The rest of the interface remains available. Aircraft data can be shown after configuring an optional OpenSky Network or ADS-B Exchange account. A Hamlib-compatible rotator is optional specialized hardware.
